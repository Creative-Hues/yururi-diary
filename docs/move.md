# 新しいアドレスへの引っ越し(v0.14.0〜)

## なぜ

古いアドレス `https://creative-hues.github.io/yururi-diary/` は、同じアカウントの他アプリ(めくりめくり など)と保存場所(IndexedDB・localStorage・Cache Storage)を共有している。他アプリのために「サイトのデータを消す」と、こちらの記録まで消える。そこで、このアプリ専用のアドレス `https://yururi-diary.pages.dev/`(Cloudflare Pages)に移す。`pages.dev` は Public Suffix List に入っているので、`yururi-diary.pages.dev` は単独の「サイト」になり、他のアプリと保存場所を共有しない。

## しくみ

- 同じコードを両方のアドレスに置き、`js/config.js` の `SITE`(`location.origin` で判定)で動きを変える。
  - `old`(古いアドレス):`#/move`(引っ越しの画面)。`MOVE_OPEN = true` にするか、`?move` を付けて開くと(そのタブの中だけ。リハーサル用)、起動時に引っ越しの画面で開く。引っ越す前は「今は引っ越さずに使う」で、そのタブの中では出さない
  - 引っ越しが済んだ古いアプリ(`meta.movedOut` がある):**記録できない案内だけの画面**(`enterMovedMode`)。画面の切り替えを止め、「新しいアプリを開く」「バックアップを書き出す」と「古いアイコンはホーム画面から外してね」の案内だけを出す。古いアイコンから癖で開いて記録し、記録が新旧2つに分かれるのを防ぐため。引っ越したそのタブでもすぐ切りかわり、別のタブ・窓も、画面に戻ってきたときに切りかわる
  - 開発者用の戻し方:古いアドレスに `?old-dev` を付けて開くと、そのタブの中だけ、これまでどおり使える(起動時は `#/move`)。そこで「(開発者用)引っ越し済みの印を外す」を押すと `movedOut` を消し、古いアプリはまた記録できるようになる。本人向けの画面・ヘルプには出さない
  - `new`(新しいアドレス):`#/move-in`(受け取る画面)。記録がまだ無ければ、ホームに「古いアプリの記録を、ここに移す」を出す
  - localhost では 8123番 = old、8124番 = new(PC での確認用)
- 受け渡し(`js/move.js`)
  1. 古いアプリで「ファイルを保存する」:いつものバックアップファイル(.json)をダウンロードに保存(`lastBackupAt` も更新)
  2. 「新しいアプリを開く」:`window.open(新しいアドレス#/move-in/<ファイル名>)`。ファイル名は探すときの目印で、日時しか入っていない
  3. 新しいアプリ → `opener` に hello(宛先を古いアドレスに限定して、0.7秒ごと)
  4. 古いアプリは、送り主が新しいアドレスで、かつ自分が開いた窓のときだけ、data(バックアップと同じ形 + 持っていく meta)を返す
  5. 新しいアプリは、送り主が古いアドレスで、かつ自分を開いた窓のときだけ受け取る。記録があれば置き換えの確認を出す。`restoreBackup`(いまの記録は `importUndo` にとっておく)→ meta を書く → 受け取った行がすべて同じ中身で入ったか確かめる → done(件数)を返す
  6. 古いアプリは件数を見比べ、合っていれば `meta.movedOut` を書く。**古いアプリの記録は消さない**
- 持っていく meta:`anonId`・`lastBackupAt`・`lock`・`feedback`・`draft:*`。`lock` の `credentialId`(指紋)は外し、`failCount`・`waitUntil` は戻す(指紋はアドレスごとの登録なので、新しいアプリで登録し直す)
- 受け取れないとき:新しいアプリは、`opener` が無ければすぐ、あっても5秒で届かなければ「ファイルから読み込む」を大きく出す。ファイルにはロック・下書きが入っていないので、ロックはオフになる(案内を出す)。古いアプリでは8秒たつと「自動で移らなかったときは」を出し、「新しいアプリで読み込めた」で `movedOut`(how: file)を書ける

### 選ばなかった方法

- URL の # にデータを入れる:閲覧履歴(Google アカウントの同期を含む)に記録が残るため
- iframe で古いアドレスを読み込む:別のサイトの中の iframe は保存場所が分けられ(Storage Partitioning)、古い記録が見えないため

## Pixel(ホーム画面のアプリ)で起きうること

- ホーム画面のアプリ(WebAPK)から別のアドレスを開くと、Chrome のタブか、アプリの中の簡易ブラウザ(Custom Tab)で開く。このとき `opener` が無くなることがあり、直接の受け渡しができない → 新しいアプリはすぐ「ファイルから読み込む」を出す
- 簡易ブラウザで受け取った記録も、Chrome 本体と同じ保存場所に入るので、あとで新しいアプリをホーム画面に追加しても、そのまま見える
- ファイルを選ぶ画面は「最近使ったファイル」から開き、いちばん上がさっき保存した引っ越し用のファイルになる

## Cloudflare Pages

- GitHub の `Creative-Hues/yururi-diary` の `main` につなぎ、push するたびに自動で公開(ビルドなし、出力ディレクトリはリポジトリの一番上)
- `_headers`:`sw.js`・`js/version.js` は毎回確かめる(`no-cache`)、ほかに nosniff・no-referrer・DENY
- Cloudflare Pages は `/index.html` を `/` に転送する。転送された応答を Service Worker が画面として返すと開けなくなるため、`sw.js` は `./` を保存して返す(v0.14.0 で `./index.html` をやめた)

## 段階

1. 段階B(v0.14.0):このしくみを入れる。`MOVE_OPEN = false` なので、Mちゃんの画面は何も変わらない。`?move` でリハーサル
2. 段階C(本番):`MOVE_OPEN = true` にして公開 → Mちゃんの Pixel で引っ越し
3. 段階D(古い記録を消す)は行わない(2026-10-08 に決定)。古いアドレスは記録できない案内画面にして、古い記録は予備としてそのまま残す

## 元に戻すとき

- 新しいアプリで問題があれば、古いアプリはそのまま使える(記録は消していない)。`MOVE_OPEN = false` に戻して公開すれば、引っ越しの画面も出なくなる
- 引っ越し済みの古いアプリを、また記録できるようにするには、`?old-dev` で開いて「(開発者用)引っ越し済みの印を外す」を押す(その端末の古いアプリだけ)
