# ロック(パスコード・指紋認証)

## しくみ

- 設定は `meta` ストアの `lock` に保存する(端末ごと。バックアップには入れない)。
- パスコードはそのまま保存せず、PBKDF2-SHA256(150,000回・ランダムなソルト)でハッシュにして保存する。
- 指紋認証は WebAuthn の端末内の認証器(platform authenticator)を使う。サーバーがないので、「その端末で本人確認(UVフラグ)が通ったか」と「登録したものと同じ鍵か」だけを確かめる。署名の検証はしない。
- ロックがかかるとき:アプリを開いたとき(毎回)、アプリから離れて設定した時間(1/3/5/10/30分、初期5分)以上たってから戻ったとき。
- まちがえたとき:5回ごとに待ち時間(30秒 → 1分 → 5分、それ以降は5分)。待てばまた入力できる。待ち時間は保存されるので、開き直しても消えない。指紋認証は待っている間も使える。

## 守れること

- スマホを手に取った人が、アプリを開いて記録を見ること(のぞき見)。
- 少し目を離したすきに見られること(離れて戻るとロック)。
- パスコードを総当たりで試すこと(5回ごとに待つので、画面からの総当たりには時間がかかる)。

## 守れないこと(限界)

- **データは暗号化していない**。端末の中の IndexedDB にそのまま入っているので、次のような人からは守れない。
  - スマホのロックを解除できて、パソコンにつないで開発者ツール(USB デバッグ)を使える人。
  - スマホを解析(root 化など)できる人。
- **4桁のパスコードは1万通りしかない**。ハッシュにしていても、ハッシュを取り出せる人なら、パソコンで総当たりして割り出せる。ハッシュにしているのは、パスコードをそのまま見られないようにするため。
- アプリの画面の仕組み(JavaScript)で止めているだけなので、ブラウザを細工できる人は飛ばせる。
- Android の「最近使ったアプリ」の画面に、離れる直前の画面が小さく映ることがある(Web アプリからは止められない)。
- `creative-hues.github.io` の別のアプリ(ひとつやね など)は同じ保存場所を使うので、理屈の上ではそちらのアプリからこのアプリのデータを読める(どちらも自分で作ったアプリなので、実際の問題はない)。

## パスコードを忘れたとき

本人向けの同じ案内が、ロック画面の「パスコードを忘れたら」と、ヘルプ(ホーム左上の「?」)の「パスコードを忘れたとき」にある(どちらも `js/forgot-guide.js`)。

1. ロック画面の「パスコードを忘れたら」→ いちばん下の「このアプリのデータを消す」(確認2回。2回目は「けす」と入力)。
   ゆる〜り日記のデータ(IndexedDB の `yururi-diary` と、`yururi-diary:` で始まる localStorage)だけを消し、同じアドレスのほかのアプリのデータは消さない(`js/wipe.js`)。
2. アプリが開き直るので、設定 → バックアップ → 読み込む。
3. ロックの設定はバックアップに入っていないので、ロックはオフの状態で記録が戻る。

ロックを開けずに使えるが、見られるもの(記録の中身・件数)はなく、できるのは消すことだけ(出すのは、どのファイルを使うか分かるよう、最後のバックアップの日時だけ)。
以前の Chrome の「サイトのデータを消す」でも、ロックなしで消せたので、のぞき見への守りは弱くならない。いたずらや押しまちがいで消えないよう、「けす」の入力を求めている。

## 端末の指紋の状態による違い(Pixel)

- 画面ロックがない端末:WebAuthn が使えないので、パスコードだけになる。
- 画面ロック(PIN など)はあるが、指紋を登録していない端末:「指紋認証」の確認で、Android の画面ロック(PIN・パターン)を求められる。
- あとで端末の指紋を全部消した・登録しなおした:指紋認証が通らなくなることがある。そのときはパスコードで開いて、設定 → ロック で指紋認証を「解除する」→「登録する」。

## PC の Chrome で指紋認証を試す(DevTools の WebAuthn パネル)

1. アプリを開いた状態で F12(開発者ツール)を開き、デバイスモード(Pixel)にする。
2. 開発者ツールの右上「︙」→ More tools → **WebAuthn** を開く。
3. 「**Enable virtual authenticator environment**」にチェックを入れる。
4. 「New authenticator」で次のように設定して **Add** を押す。
   - Protocol:**ctap2**
   - Transport:**internal**(端末内の認証器のふり)
   - Supports resident keys:オフでよい
   - Supports user verification:**オン**
5. アプリの 設定 → ロック → 指紋認証「登録する」(または、オンにした直後の「指紋認証を登録する」)。
   パネルの Credentials に1件増えれば登録できている。
6. 「今すぐロックする」→ ロック画面の「指紋」を押すと開く。アプリを開き直すと、自動で指紋の確認が走って開く。
7. 指紋が通らない場合を試す:パネルの認証器の「**Is user verified**」のチェックを外して「指紋」を押す →「パスコードで開けます」と出て、パスコードで開ける。
8. 認証器がなくなった場合を試す:パネルで認証器を **Remove** → 開き直すとパスコードで開ける。

※ 仮の認証器を有効にしている間は、PC の本物の Windows Hello などの代わりに仮の認証器が使われる。
※ Windows Hello が使える PC では、仮の認証器がなくても「登録する」が出て、Windows Hello の画面が出る。
